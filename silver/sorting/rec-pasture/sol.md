**问题转化**

要数的是"能被矩形框出的牛集合"数量。直接枚举矩形不可行（坐标大、且多个矩形对应同一集合会重复）。转化的钥匙：x 坐标互不相同 → 每个非空集合有唯一的最左牛 i 和最右牛 j。把 (i, j) 当作集合的"身份证"，按身份证分类计数，不重不漏。

**固定 (i, j) 后数集合**

左右边界被钉死：左贴 i、右贴 j（再外扩最左/最右就换人）。x 介于两者之间的牛构成一条竖带，它们进不进圈只取决于上下边界。

- 矩形必须罩住 i 和 j，即 y 方向至少覆盖 [min(yᵢ,yⱼ), max(yᵢ,yⱼ)]；
- 竖带里 y 落在这个区间内的牛被迫入圈，没有选择；
- 竖带里 y 低于区间的有 a 头 → 下边界有 a+1 种停法（吞 0 到 a 头）；
- 高于区间的有 b 头 → 上边界 b+1 种；
- y 也互不相同保证每种停法组合对应不同集合，故贡献 **(a+1)×(b+1)**。

i = j 时竖带宽度为零，a = b = 0，贡献 1（单牛集合），公式自动兼容。

**总答案**

> ans = Σ_{所有 i ≤ j 的牛对} (a+1)×(b+1) + 1（空集）

**高效实现**

枚举 O(N²) 对，每对若朴素扫描数 a、b 是 O(N³)，N=2500 超时。优化：

1. 坐标离散化：x、y 各自替换成 1..N 的排名（相对顺序不变，计数结果不变）；
2. 建二维前缀和 `psum[x][y]` = x 排名 ≤ x 且 y 排名 ≤ y 的牛数，O(N²) 预处理；
3. a = "x 排名在 [rank_x(i), rank_x(j)]、y 排名 < min(...)"的矩形区域计数，O(1) 查出，b 同理；
4. 实践中常用的等价写法（也是你代码想写的那种）：按 y 排序后枚举 (i, j) 作为集合里 y 最低/最高的牛，用前缀和数"x 方向左侧可扩的选择数 × 右侧可扩的选择数"。两种视角对称等价，选一个坐标轴当"身份证"轴、另一个轴数扩展即可。

总复杂度 O(N²)，2500² ≈ 6×10⁶，轻松通过。答案用 long long。
