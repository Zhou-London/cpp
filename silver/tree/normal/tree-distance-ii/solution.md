这是经典的**换根 DP（rerooting）**题。暴力做法是对每个点跑一次 BFS，复杂度 O(n²)，n = 2·10⁵ 会超时，所以要利用相邻节点答案之间的关系，做到 O(n)。

## 核心观察

假设已经知道父节点 `p` 的答案 `ans[p]`，现在把"视角"从 `p` 移到它的孩子 `c`：

- `c` 子树里的 `sz[c]` 个点，离新视角都**近了 1**
- 其余 `n - sz[c]` 个点，都**远了 1**

所以：

```
ans[c] = ans[p] - sz[c] + (n - sz[c]) = ans[p] + n - 2*sz[c]
```

只要有一个点的答案和所有子树大小，其他点的答案都能 O(1) 推出来。

## 两遍遍历

1. **第一遍（自底向上）**：以 1 为根，求每个点的子树大小 `sz[v]`，同时求 `ans[1]`，也就是所有点的深度之和。
2. **第二遍（自顶向下）**：从根出发，用上面的公式把答案从父亲传给孩子。

## 用样例验证

树：1-2，1-3，3-4，3-5，以 1 为根。

- 深度之和：`ans[1] = 1 + 1 + 2 + 2 = 6`
- `sz[2]=1, sz[3]=3, sz[4]=1, sz[5]=1`
- `ans[2] = 6 + 5 - 2·1 = 9`
- `ans[3] = 6 + 5 - 2·3 = 5`
- `ans[4] = ans[5] = 5 + 5 - 2·1 = 8`

结果 `6 9 5 8 8`，与样例一致。

## 两个容易踩的坑

- **要用 `long long`**：链状的树答案能到约 n²/2 ≈ 2·10¹⁰，超出 int 范围。
- **递归深度**：树退化成链时深度为 2·10⁵，递归 DFS 可能爆栈，所以上面用 BFS 序代替递归。

这个"先固定根算一遍，再推导换根时答案如何变化"的套路很通用，比如 Tree Distances I（每个点的最远距离）也是同样的思路，只是转移时要维护的信息更多一些。
